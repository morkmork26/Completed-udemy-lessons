What is Generative AI

💡 Core Insight

Generative AI sits at the convergence of machine learning and deep learning, distinguished by its ability to produce novel, human-quality content rather than merely classify or predict from existing data.

Artificial intelligence is the broad discipline of enabling machines to simulate human reasoning and decision-making. Within AI, machine learning (ML) narrows the goal: instead of explicitly programming every decision, ML systems learn from data, improving iteratively through exposure to labeled examples. Deep learning extends this further by using multi-layered neural networks that can extract hierarchical representations from unstructured data such as images, audio, and text. Generative AI represents a distinct capability layer within deep learning. Where traditional ML classifies or predicts, generative models synthesize entirely new outputs — text, images, audio, video, and code — that were never explicitly in the training data. Foundational architectures like Generative Adversarial Networks (GANs) and transformers enabled this leap, with transformers in particular underpinning the large language models that power tools like ChatGPT. The result is a class of AI that behaves less like a lookup engine and more like a creative collaborator.

Generative AI is like a student who read billions of documents and can write new essays, but sometimes makes things up because it learned patterns, not facts.

Key Points

  • AI is the parent field; machine learning and deep learning are progressively specialized subsets of it.
  • Traditional ML learns to classify or predict; generative AI learns to create — a fundamentally different capability class.
  • GANs introduced the generator/discriminator adversarial dynamic that enables realistic synthetic media generation.
  • Transformer architecture is the breakthrough that made large-scale language generation practical and commercially viable.
  • Generative AI outputs span text, images, audio, video, and code — making it relevant across virtually every enterprise function.
  • Understanding the AI hierarchy (AI → ML → Deep Learning → Generative AI) clarifies where security boundaries need to be drawn.

What are Large Language Models

💡 Core Insight

Large language models are statistical pattern engines trained on internet-scale text that generate fluent language by predicting probable word sequences — not by understanding meaning the way humans do.

A large language model (LLM) is a deep learning system trained on massive corpora of text data to model the statistical structure of human language. During pre-training, the model learns to predict the next token in a sequence, absorbing grammar, facts, reasoning patterns, and stylistic conventions from billions of documents. This is followed by fine-tuning — a supervised phase where human feedback refines the model's behavior toward useful, accurate, and safe outputs. The critical distinction for practitioners is that LLMs do not 'understand' language in a semantic or intentional sense. They are sophisticated pattern matchers: when a model has observed that 'hot' frequently precedes 'dog,' it learns that association statistically. This architectural reality has direct security implications: LLMs can produce confident, fluent, and entirely fabricated outputs (hallucinations), they inherit biases from training data, and their knowledge is bounded by a hard cutoff date. Use cases span text generation, translation, summarization, sentiment analysis, code generation, and conversational AI — making LLMs among the most cross-functional enterprise tools ever deployed.

LLMs are like a massive autocomplete that predicts the next word based on patterns from billions of texts. Bigger models with more parameters can handle more complex predictions.

Key Points

  • LLMs learn language by predicting the next token at scale — meaning is emergent from statistics, not programmed semantics.
  • Pre-training on internet-scale data is followed by fine-tuning with human feedback to shape safe and useful outputs.
  • Hallucinations — confidently stated but factually wrong outputs — are a structural risk, not a bug to be patched.
  • A hard training cutoff date limits LLM knowledge; events after the cutoff are unknown unless augmented with retrieval tools.
  • LLMs inherit biases from training data, creating risks of toxic, racist, or misleading outputs in enterprise contexts.
  • Operational costs (compute, energy, carbon footprint) and complexity make LLMs expensive to develop, deploy, and audit.

Generative AI vs Agentic AI

💡 Core Insight

Agentic AI escalates generative AI from a conversational tool into an autonomous decision-making system that can plan, act, and modify its environment — a shift that fundamentally changes the security and risk profile.

Generative AI in its foundational form is a reactive system: it receives a prompt and produces an output, with no persistent state or ability to take actions beyond generating text. Agentic AI extends this model by giving language models the ability to reason across multiple steps, call external tools (web search, code execution, APIs, databases), maintain memory between interactions, and pursue user-defined goals autonomously over extended task horizons. The practical difference is the degree of human supervision required. A generative AI model answering a question is low-autonomy and low-risk. An agentic system browsing the web, writing and executing code, sending emails, or interacting with enterprise systems on behalf of a user introduces new attack surfaces: prompt injection through external data, unintended tool misuse, privilege escalation via API access, and loss of human oversight in multi-step decision chains. Security frameworks designed for static generative AI outputs are insufficient for agentic systems, which require controls around tool permissions, action logging, and human-in-the-loop checkpoints.

Regular GenAI is like a chef who suggests recipes; Agentic AI is like a chef who also goes shopping, cooks, and serves, making mistakes harder to catch.

Key Points

  • Generative AI is reactive (prompt in, output out); agentic AI is proactive — it plans, acts, and iterates toward a goal.
  • Agentic systems can call external tools (APIs, browsers, code runners), dramatically expanding the attack surface beyond text generation.
  • Multi-step reasoning chains in agentic AI reduce human oversight at each individual decision, compounding error and misuse risk.
  • Prompt injection becomes a critical threat in agentic AI: malicious content in external data sources can hijack the agent's actions.
  • Privilege and access control must be explicitly scoped for agentic AI; an agent with broad tool access can cause disproportionate harm.
  • Agentic AI governance requires human-in-the-loop checkpoints, action logging, and least-privilege tool permissions — not just output filtering.

Data Privacy and Confidentiality

💡 Core Insight

Every interaction with a public GenAI model is a data transfer to a third party, carrying the same regulatory and IP exposure as any cloud data sharing decision.

When employees submit prompts to public generative AI services, the data leaves organizational control and enters third-party infrastructure. This triggers legal and compliance exposure under GDPR, HIPAA, PCI-DSS, and data residency laws. Furthermore, submitted data may be used to train the AI model unless explicitly opted out, meaning proprietary information could surface in responses to other users. The Samsung semiconductor incident demonstrated that even sophisticated engineering teams can inadvertently leak trade secrets through routine AI tool usage.

Data privacy in GenAI is like talking to a stranger who has perfect memory. Everything you share might be remembered and repeated to someone else later.

Key Points

  • Data submitted to public AI tools is collected and potentially used for model retraining unless opt-out is configured
  • Regulatory frameworks (GDPR, HIPAA, PCI-DSS) apply identically to AI data transfers as to any third-party sharing
  • Samsung engineers leaked proprietary semiconductor source code and meeting notes through ChatGPT usage
  • Mitigation requires DLP tools, employee training, sanitization procedures, and contractual opt-out agreements
  • Italy temporarily banned ChatGPT over GDPR concerns, signaling regulatory enforcement is active

GenAI Provider Breach

💡 Core Insight

A breach of the GenAI provider itself exposes not just credentials but the entire history of prompts, responses, and potentially training data from all customers.

Organizations using third-party GenAI services face supply-chain risk: if the provider is breached, attackers gain access to stored conversations, API keys, user data, and potentially proprietary information embedded in prompts. The ChatGPT breach of March 2023 demonstrated this when a Redis library bug exposed other users' chat histories, payment information, and email addresses. Unlike traditional SaaS breaches, GenAI breaches can expose intellectual property, strategic plans, and source code that users submitted during normal usage.

A GenAI provider breach is like your outsourced filing cabinet getting stolen. All the conversations and data you sent to the AI service are now exposed.

Key Points

  • GenAI providers store conversation histories containing potentially sensitive organizational data
  • The ChatGPT March 2023 breach exposed chat titles, payment info, and email addresses of other users due to a Redis client bug
  • Supply-chain risk compounds: a single provider breach affects all customer organizations simultaneously
  • Breached prompt histories reveal more context than typical credential leaks since they contain thought processes and IP
  • Risk mitigation requires data minimization in prompts and contractual breach notification requirements

💡 Core Insight

Threat modeling visualizes data flows and trust boundaries in LLM deployments, enabling teams to identify and document AI-specific risks before selecting mitigations.

Threat modeling is an application-specific risk assessment methodology that surfaces security issues missed by standard probability-impact matrices. By diagramming how data flows through an LLM system, including API boundaries, trust boundaries, data stores, and external integrations, security teams and developers can collaboratively map where attacks such as prompt injection, SSRF, DDoS, and data leakage are most likely to occur. The STRIDE framework structures this analysis by categorizing threats into Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, and Elevation of Privilege. Applied to GenAI, STRIDE forces practitioners to document each threat category against the specific architecture before jumping to controls. The output is an actionable risk inventory that drives control selection, not the other way around. Threat modeling is as much a cultural practice as a technical one: teams that diagram their systems together develop a shared threat vocabulary that improves ongoing security decisions.

Threat modeling for GenAI is like planning home security by thinking like a burglar. You map every entry point, asset, and potential attacker to find gaps.

Key Points

  • Standard risk assessments (Excel-based probability/impact matrices) miss application-specific context; diagramming the system exposes risks that checklists cannot capture.
  • Two common GenAI architectures require different threat profiles: publicly hosted LLMs (e.g., ChatGPT API) versus internally hosted open-source models have distinct attack surfaces.
  • STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) provides a structured vocabulary for documenting GenAI threats before selecting controls.
  • Threat modeling is a team activity: sitting developers, cybersecurity professionals, and architects together to create the diagram builds a proactive security culture.
  • The four core threat modeling questions are: What are we building? What can go wrong? What will we do about it? Did we do a good enough job?
  • Control selection should follow risk documentation; organizations that skip threat modeling often implement controls that address the wrong risks.

The AWS Generative AI Security Scoping Matrix aligns security responsibilities and controls to five distinct deployment scopes, ensuring organizations apply the right level of protection to the right type of GenAI workload.

The AWS Generative AI Security Scoping Matrix is a structured framework released by Amazon Web Services that categorizes GenAI deployments into five progressive scopes based on the degree of organizational ownership and customization. Each scope carries a distinct security responsibility profile, and the matrix maps six security dimensions across all five scopes, enabling organizations to determine which controls are owned by the provider, which are shared, and which are fully the organization's responsibility. The five scopes range from Scope 1 (direct use of a publicly accessible GenAI application such as ChatGPT or Gemini, with minimal organizational control) to Scope 5 (a fully self-trained model where the organization controls the entire stack). Intermediate scopes cover enterprise-licensed API access (Scope 2), pre-trained foundation models accessed via cloud APIs (Scope 3), and fine-tuned models (Scope 4). The six security dimensions evaluated across scopes are: data governance, identity and access management, application security, threat modeling, security controls, and resilience. While the framework references AWS services, its conceptual structure applies to any cloud or on-premises GenAI deployment.

The AWS scoping matrix is like a menu at a restaurant. Depending on how much AI capability you consume vs. build, your security responsibilities change.

Key Points

  • Five deployment scopes reflect increasing organizational control: from public consumer apps (Scope 1) to fully self-trained models (Scope 5); each scope requires a different security posture.
  • Data governance responsibilities escalate with scope: Scope 1 requires only user awareness, while Scope 5 demands full training data lineage, access control, and compliance coverage.
  • Identity and access management at Scope 3+ requires use of cloud provider IAM policies to restrict model access, provisioning, and API permissions.
  • Threat modeling becomes mandatory at Scope 3 (enterprise API integration) and above, where OWASP LLM Top 10 risks such as prompt injection and insecure output handling fully apply.
  • Resilience risk is highest for organizations heavily dependent on Scope 1/2 providers; outages in public GenAI services can halt operations without organizational control over recovery.
  • The matrix can be adapted beyond AWS: the scope taxonomy and security dimensions apply equally to Azure OpenAI, Google Vertex AI, and on-premises deployments.

OWASP Top 10 For LLMs - 2025

💡 Core Insight

The OWASP LLM Top 10 for 2025 extends its 2023 baseline with four new entries reflecting real-world agentic deployments, system prompt exploitation, RAG vulnerabilities, and resource overconsumption.

The OWASP Top 10 for Large Language Model Applications is a community-driven, freely available risk taxonomy maintained by the OWASP Foundation. Updated in 2025 based on real-world LLM deployment experience accumulated since 2023, the list identifies the ten most critical security risks for organizations building or operating LLM-based systems. It is designed to be accessible to developers, security professionals, and auditors simultaneously, balancing technical depth with practical guidance. The 2025 update retains five risks from the original 2023 list (Prompt Injection, Sensitive Information Disclosure, Supply Chain Attacks, Data and Model Poisoning, and Improper Output Handling) while expanding two existing entries and introducing two new ones to reflect the maturation of agentic AI frameworks and Retrieval-Augmented Generation (RAG) architectures. The list functions as a risk taxonomy and common language for organizational risk assessment, not as a binary compliance checklist. Practitioners are advised to build a risk matrix mapping each OWASP entry to their specific LLM inventory by likelihood and impact, enabling prioritized and auditable security programs.

OWASP Top 10 for LLMs is like a most-wanted list of AI vulnerabilities. It tells defenders exactly where attackers are most likely to strike.

Key Points

  • Five risks are retained from 2023: Prompt Injection, Sensitive Information Disclosure, Supply Chain Attacks, Data and Model Poisoning, and Improper Output Handling.
  • Excessive Agency (LLM06) is expanded to reflect agentic AI frameworks where LLMs can autonomously take actions; overly permissive agent permissions increase blast radius of any compromise.
  • System Prompt Leakage (LLM07) is newly added after real-world exploits demonstrated that system prompts can be extracted and used to reverse-engineer or bypass LLM behavior.
  • Vector and Embedding Weaknesses (LLM08) addresses RAG knowledge base vulnerabilities; attackers target these stores because they contain sensitive organizational data.
  • Unbounded Consumption (LLM10) expands the previous denial-of-service entry to cover quota exhaustion and runaway cost in large-scale LLM deployments.
  • The OWASP list should be used as a shared risk language and a living document for continuous assessment, not as a one-time pass/fail compliance audit.
